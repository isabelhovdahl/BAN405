# AI Guidelines for Learning to Code

AI assistants can write working Python faster than you can. They are also the easiest way to get through a programming course without learning to program.

**One rule settles most cases: use AI to understand things, not to produce things.**

## Quick reference

| ✅ Helps you learn | ❌ Feels like progress, but isn't |
| --- | --- |
| Asking what an error message means | Pasting the error and applying the fix unread |
| Asking for a hint when you are properly stuck | Asking for the solution |
| Asking it to explain code you wrote yourself | Asking it to write code that you then read |
| Asking it to review a solution you finished | Asking it to produce the solution |
| Asking for extra practice problems | Asking for the answers to them |
| Typing code out yourself | Copying and pasting |

## The test

Two questions. If either answer is no, the code is not yours yet:

- Could you delete the file and write it again from an empty editor?
- Can you explain every line, and why it is there rather than something else?

> 📝 **Note:** Reading a correct solution feels like understanding it. It usually isn't. Recognizing code and generating it from a blank file are different skills — and only the second one is what you are here to build.

## Five habits

1. **Attempt it first.** Write something before you ask anything. It does not need to work.
2. **Ask for hints, not answers.** Tell the assistant explicitly what *not* to do.
3. **Ask it to explain — including code that already works.** Some of the best use of AI comes *after* you have solved something.
4. **Type it out, don't paste.** Typing forces you through every character and surfaces what you don't understand. Pasting hides it.
5. **Check it.** Assistants invent functions and arguments in the same confident tone they use when correct. Run the code, and verify claims against the official Python documentation.

## Prompts that keep it in tutor mode

```
Don't give me the code. Give me a hint about what to look at next.

Explain what this error message means, but don't fix my program.

Ask me questions to help me find the bug myself.

Explain this line by line: <your code>

Give me three more practice problems like this one - without the solutions.
```

> ⚠️ **Warning:** The use that catches people out is reaching for AI to keep pace after falling behind. It is the most understandable one and the most damaging, because it hides the gap instead of closing it — and the gap only becomes visible in an exam. Ask for help instead.

## Honesty is good practice everywhere

- **Presenting AI-generated work as your own is dishonest** — in a course, in a thesis, at work. Editing the output afterwards does not change that.
- **Declaring AI use is normal practice, not an admission of wrongdoing.** Universities, journals, and employers increasingly expect it.
- **Get into the habit now:** note which tool you used and what you used it for.

> 📝 **Note:** Specific rules for individual assignments and assessments are published separately, along with your institution's own guidance on generative AI. Those take precedence over anything here.

## Keep private things private

Anything you type into an online AI tool leaves your computer and may be stored by the provider. Don't paste in personal data, confidential material, or anything you don't have the right to share. It rarely matters for coursework — it matters a great deal at work.
